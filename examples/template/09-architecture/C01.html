C01 The architecture at four zoom levels (C4)

Four levels, from farthest to closest. The rule is simple: each level answers a different question, and mixing two of them into one picture is how most architecture diagrams end up a wall of little boxes.

1 Context — the system in the world

Who uses it, and what it talks to.

The diagram, as text — so it falls under the traffic light like any other block:

flowchart LR
  P([the person]) --> S[your system]
  S --> E1[external system]
  S --> E2[another external one]

This level is for people who will not write code. If a director does not follow it, it is wrong.

2 Containers — the parts that run

Everything that starts up on its own.

The diagram, as text — so it falls under the traffic light like any other block:

flowchart TD
  W[browser] --> A[API]
  A --> B[(database)]
  A --> F[queue]

One box per process: app, API, database, queue, job. Say what each one is written in and how the others talk to it.

3 Components and code

Only where it pays off.

Draw the third level only for the complicated parts. The fourth — the code — almost never pays: it ages in days, and the code is already there to be read.
